The concepts

TermPlain versionAnalogyEngineer's version
RepositoryA project folder that carries its own historyThe operations binderA git-tracked directory plus a hidden .git database
BranchA parallel line of work; main stays untouchedSand table rehearsalA movable pointer to a commit
CommitA permanent labeled snapshotA signed duty log entryAn immutable object: tree, parent, author, message, SHA
Push / pullPush sends mine up; pull brings theirs downRadio my log up to headquartersUpload to a remote branch; fetch and integrate
Local vs remoteMy copy versus the shared, backed-up copyMy ruck versus HQ master filesA full clone versus a named remote, origin
Pull requestA request to combine branches after review (I pushed to main solo)Staff review before the commander signsA hosted merge request with a diff and required checks
MergeJoins two lines of work into oneAn approved amendment folded into the orderIntegrates histories and flags conflicts
Frontend vs backendWhat the visitor sees versus the server that stores dataShop window versus stockroomClient renders UI; server owns persistence and auth
CIA robot that reruns the checks on every pushA second inspector on every load-outGitHub Actions; both repos show a green run
Acceptance testA pass or fail check for one requirementThe end state in an operations orderAutomated test per criterion, run by npm run check

The three traps the spec set

TrapHow I handled it
Typed prices vs the catalogEvery price and plan comes from lib/copper/catalog.ts. The grader swaps prices to prove nothing is typed.
"Never records" privacy conflictOlder documents conflict. I followed the 2026 policy and never claim "never records."
Off-brand colorsSix brand colors as named tokens in app/globals.css; test AC-4.1 rejects any other hex.
